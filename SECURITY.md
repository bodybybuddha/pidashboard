# Security Policy

## Supported Versions

Security updates are tracked on active development branches and released to `main` through the `dev` promotion flow.

## Reporting a Vulnerability

- Do not open public issues for sensitive vulnerabilities.
- Report privately to repository maintainers with reproduction details and impact.
- Include affected components, logs, and mitigation ideas when available.

## Security Baseline

- Do not commit secrets, credentials, or broker keys.
- Use environment variables for sensitive configuration.
- Keep dependencies pinned where practical and review updates.
